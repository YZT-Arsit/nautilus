````markdown
# 自研数据接入与历史特征工程模块

## 1. 项目目标

本模块用于构建一套可复用的量化数据接入、分钟线构建、历史数据管理与特征工程框架。

核心目标是：

1. 将自研数据接入模块从策略逻辑和执行框架中抽象出来；
2. 将历史行情数据、历史特征数据、合约/标的信息统一纳入历史数据体系；
3. 支持分钟线构建、历史特征计算、特征落盘和特征查询；
4. 保证自研核心模块不与 Nautilus Trader 耦合，可复用到其他项目中。

当前设计中，Nautilus 仅作为可选 adapter 或 provider 存在，不进入 `data_engine` 和 `feature_engine` 的核心模块。

---

## 2. 整体架构

```text
外部行情源 / CSV / Parquet / Hive Parquet / 可选 Nautilus adapter
        ↓
data_engine
        ↓
标准 BarEvent / 标准 Polars DataFrame
        ↓
MinuteBarBuilder / HistoricalFeatureBuilder
        ↓
market_data / feature_data Hive Parquet
        ↓
MarketDataReader / FeatureDataReader
        ↓
训练、回测、实盘 warmup、研究分析
````

模块分为四层：

| 层级      | 模块                                       | 作用                                                                    |
| ------- | ---------------------------------------- | --------------------------------------------------------------------- |
| 数据接入层   | `data_engine`                            | 统一读取 CSV、Parquet、Hive Parquet、mock/live provider，并归一化为标准事件或 DataFrame |
| 分钟线构建层  | `MinuteBarBuilder`                       | 将 tick / quote / bar 数据聚合为 1m / 5m / 15m OHLCV 分钟线                    |
| 特征工程层   | `HistoricalFeatureBuilder`               | 从行情 DataFrame、BarEvent 或 `market_data` 中计算历史特征                        |
| 历史数据读取层 | `MarketDataReader` / `FeatureDataReader` | 分别读取历史行情数据和历史特征数据                                                     |

---

## 3. 模块边界

### 3.1 解耦原则

本模块遵守以下边界：

```text
data_engine core 不依赖 Nautilus
feature_engine core 不依赖 Nautilus
feature_engine execution/storage 不依赖 Nautilus
数据接入逻辑不写入策略层
Nautilus 相关逻辑只能放在 adapters/providers 中
```

也就是说，自研模块应能在没有 Nautilus 环境的普通 Python 项目中运行：

```text
CSV / Parquet / Hive Parquet
        ↓
data_engine
        ↓
feature_engine
        ↓
historical_data
```

### 3.2 Nautilus 的角色

Nautilus 不是核心依赖，只是可选接入方式。例如：

```text
data_engine/adapters/nautilus_catalog.py
```

该 adapter 仅用于从 Nautilus catalog 中读取已有行情数据，核心模块不会主动 import Nautilus。

## 4. 历史数据体系

本项目中，历史数据不只包括原始行情，还包括历史特征和合约信息：

```text
历史数据 = market_data + feature_data + instruments + manifests
```

| 数据类型           | 说明                                          |
| -------------- | ------------------------------------------- |
| `market_data`  | 历史行情数据，例如 tick、bar、OHLCV、分钟线                |
| `feature_data` | 由行情数据计算得到的历史特征，例如 MA、RSI、MACD、VWM           |
| `instruments`  | 合约/标的信息，例如 symbol、exchange、tick size、expiry |
| `manifests`    | 数据批次、特征版本、参数、来源、行数等元信息                      |

核心原则：

> 特征数据不是临时变量，而是历史数据资产的一部分。计算完成后应落盘、登记 manifest，并可被训练、回测、实盘 warmup 等下游任务复用。

```text
      manifest-*.parquet
```

## 6. 主要接口

### 6.1 数据接入接口

#### `load_events(data_config)`

统一读取不同来源的数据。

```python
from data_engine import load_events

warmup_events, live_events = load_events({
    "mode": "csv_bars",
    "path": "data/bars.csv",
    "instrument_id": "IH2303.CFFEX",
    "timestamp_column": "event_time_ns",
    "timestamp_unit": "ns",
})
```

支持的数据源模式包括：

| mode                | 说明                              |
| ------------------- | ------------------------------- |
| `synthetic`         | 合成历史行情                          |
| `csv_bars`          | CSV 行情文件                        |
| `parquet_bars`      | Parquet 行情文件                    |
| `hive_parquet_bars` | Hive Parquet 历史行情               |
| `live_synthetic`    | 本地模拟实时流                         |
| `live_gateway`      | 实盘网关接口，当前以 mock / provider 占位为主 |
| `nautilus_catalog`  | 可选 Nautilus catalog adapter     |

### 6.3 分钟线构建接口

```python
from feature_engine.services.minute_bar_builder import MinuteBarBuilder

builder = MinuteBarBuilder(
    asset_class="future",
    exchange="CFFEX",
)

result, paths = builder.build_and_write(
    ticks,
    instrument_id="IH2303.CFFEX",
    market_root="historical_data/market_data",
    frequency="1m",
    trading_date="2026-05-26",
    strict=True,
)
```

该接口完成：

```text
tick / quote / bar
        ↓
1m / 5m / 15m OHLCV
        ↓
market_data Hive Parquet
```

分钟线输出字段包括：

```text
instrument_id
symbol
ts_event
open
high
low
close
volume
turnover
trading_date
frequency
volume_is_synthetic
asset_class
exchange
```

说明：

* `strict=True` 时，如果分钟线存在 OHLC 非法、重复时间戳、时间非单调等问题，会拒绝落盘。
* 如果 volume 来自 synthetic tick count，会通过 `volume_is_synthetic` 标记，避免把合成量误认为真实成交量。

### 6.4 历史特征构建接口

```python
from feature_engine.services.historical_feature_builder import HistoricalFeatureBuilder

builder = HistoricalFeatureBuilder(
    features=["sma_20", "rsi_14", "vwm_20"],
)

df = builder.build_from_market_store(
    "historical_data/market_data",
    instrument_id="IH2303.CFFEX",
    frequency="1m",
    trading_date="2026-05-26",
    asset_class="future",
    exchange="CFFEX",
)

paths = builder.write_feature_data(
    df,
    feature_root="historical_data/feature_data",
    manifest_root="historical_data/manifests",
    asset_class="future",
    exchange="CFFEX",
    frequency="1m",
    trading_date="2026-05-26",
    instrument_id="IH2303.CFFEX",
    mode="overwrite",
)
```

支持的输入方式：

```python
builder.build_from_dataframe(df)
builder.build_from_events(events)
builder.build_from_market_store(...)
```

当前可用特征包括：

```text
sma_20
rsi_14
macd
vol_30
vwm_20
vwm_zscore_60
```

默认写入新版平级 `feature_data` 布局。旧布局仅通过显式参数保留：

```python
builder.write_feature_data(..., legacy_layout=True)
```

### 6.6 历史特征读取接口

```python
from feature_engine.storage.feature_reader import FeatureDataReader

reader = FeatureDataReader(
    "historical_data/feature_data",
    manifest_root="historical_data/manifests",
)

features = reader.scan_features(
    trading_date="2026-05-26",
    frequency="1m",
    instrument_id="IH2303.CFFEX",
    columns=["symbol", "ts_event", "sma_20", "rsi_14", "vwm_20"],
)
```

如果不指定 `feature_group`，读取器会自动跨 `technical`、`volume` 等 group 合并，形成一张特征矩阵：

```text
symbol
ts_event
sma_20
rsi_14
vwm_20
...
```

查询某个分区下可用特征：

```python
available = reader.available_features(
    trading_date="2026-05-26",
    instrument_id="IH2303.CFFEX",
    frequency="1m",
)
```

### 7.2 构建历史特征

```bash
python scripts/build_historical_features.py \
  --market-root historical_data/market_data \
  --feature-root historical_data/feature_data \
  --manifest-root historical_data/manifests \
  --trading-date 2026-05-26 \
  --instrument-id IH2303.CFFEX \
  --asset-class future \
  --exchange CFFEX \
  --frequency 1m \
```

如需兼容旧布局：

```bash

  --market-root historical_data/market_data \
  --feature-root historical_data/feature_data \
  --manifest-root historical_data/manifests \
  --trading-date 2026-05-26 \
  --instrument-id IH2303.CFFEX \
  --frequency 1m \
  --features sma_20,rsi_14,vwm_20 \
  --legacy-layout
```

新项目不建议使用 `--legacy-layout`。

## 10. 当前未完成项

当前仍有以下待办：

1. **国内期货夜盘 trading_date 归属**

   当前交易日推导仍是简化逻辑。对于国内期货夜盘，建议由上游显式传入 `trading_date`，或后续接入交易日历。

2. **真实 CTP / 柜台 provider**

   当前 CTP / 柜台 provider 仍是占位实现。真实接入需后续在服务器环境中实现。

3. **dataset_manifest**

   当前 feature manifest 已支持，market_data 的 dataset-level manifest 仍可继续补强，用于记录行情导入批次、来源、行数、schema hash 等信息。

4. **更多实盘级数据质量检查**

   当前已覆盖 OHLC 合法性、重复 timestamp、时间单调性、volume synthetic 标记。后续可继续增加缺失分钟、交易时段、停牌/无行情、夜盘跨日等检查。
