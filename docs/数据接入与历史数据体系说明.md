# 数据接入与历史数据体系说明

> 面向团队 / 老板的说明文档。介绍当前自研数据接入层与历史数据体系的设计、
> 已实现能力、落盘结构、使用方式，以及尚未完成的部分。

---

## 1. 历史数据的定义

在本项目里，**历史数据 = 历史行情数据 + 历史特征数据 + 合约/标的信息**。
三者都属于统一的历史数据体系，都按 Hive-style Parquet 管理、查询、复用。

| 类别 | 含义 | 典型内容 |
| --- | --- | --- |
| 历史行情数据（market_data） | 原始市场数据 | bar / tick / OHLCV / volume |
| 历史特征数据（feature_data） | 由行情派生、计算落盘的特征 | MA、RSI、VWM、rolling volatility、derived features |
| 合约/标的信息（instruments） | 合约静态元数据 | symbol、exchange、market_type、contract_size、tick size、precision、expiry、active |

核心观点：**特征数据不是临时变量，而是历史数据的一部分**。一旦计算完成就
落盘、登记 manifest，供训练、回测、实盘 warmup 反复复用，而不是每次重新算。

## 2. 当前实现的数据链路

### 2.1 data_engine（自研数据接入层，不依赖 Nautilus Trader）

统一输出 `BarEvent`，支持以下数据源（`mode`）：

| mode | 说明 | 状态 |
| --- | --- | --- |
| `synthetic` | 合成行情，本地冒烟 | 已实现 |
| `csv_bars` | 单个 CSV 行情文件 | 已实现 |
| `parquet_bars` / `hive_parquet_bars` | Hive 分区 Parquet 历史行情 | 已实现 |
| `live_synthetic` | 合成实时流（无网络） | 已实现 |
| `live_gateway` | 准实盘网关骨架（mock + 真实 provider 占位） | mock 已实现，真实 provider 为占位 |

关键对象与函数：

- `BarEvent`：标准事件（字段 `instrument_id`、`event_time_ns`、OHLCV）。
- `bars_to_polars(events)`：`BarEvent` 列表 → Polars DataFrame，并把
  `instrument_id` 映射为 `symbol`、`event_time_ns` 还原为 UTC `ts_event`
  （同时保留原始字段，保证可无损回转）。
- `polars_to_bars(df)`：DataFrame → `BarEvent` 列表（round-trip 保持 OHLCV /
  instrument_id / timestamp）。
- `load_events(data_config)`：按 `data:` 配置返回 `(warmup_events, live_events)`。

### 2.2 feature_engine（自研特征处理层，compute 不依赖 Nautilus 执行模块）

批/流式统一的 DataFrame 特征框架：

- `FeatureDAG`：根据特征依赖解析拓扑序，自动拉入依赖特征。
- `StreamingEngine`：按 micro-batch 驱动 DAG，产出 **enriched DataFrame**
  （原始列 + 特征列）。
- `ParquetStore`：Hive-style Parquet 读写门面（分区裁剪 + 列投影）。
- `EodArchiver`：收盘归档，把 raw 列与 feature 列分别写入 raw_store / feature_store，
  采用 stage-then-commit 保证原子性，并写 manifest。
- `Manifest`：特征版本与参数管理，记录
  `feature_name / version / params_hash / computed_at / row_count / source`。
- `FeatureDataReader`：历史特征数据查询接口（见 §4）。

当前可用的真实特征名（feature registry）：

```
sma_20, rsi_14, vwm_20, vwm_zscore_60, vol_30, macd
```

### 2.3 instruments（合约/标的信息接入）

- `InstrumentInfo`：零依赖的不可变 dataclass，描述合约静态元数据。
- `StaticInstrumentProvider`：用预置列表充当 provider（测试 / 离线）。
- `CcxtInstrumentProvider`：通过 CCXT 下载交易所 market metadata 并归一化
  （`ccxt` 懒加载，未安装时报清晰错误；公共元数据无需 API key）。
- `instruments_to_polars(instruments)`：合约信息 → Polars DataFrame。
- `write_instruments_parquet(...)`：按 `exchange` / `as_of_date` 落 Hive Parquet。

> 国内期货 / CTP / 公司柜台合约信息**不走 CCXT**，后续通过独立 provider 接口接入。

## 3. 当前落盘结构（真实实现）

```
historical_data/
    market_data/
        asset_class=<asset_class>/
        exchange=<exchange>/
        frequency=<frequency>/
        trading_date=<YYYY-MM-DD>/
            part-*.parquet

    feature_data/
        feature_group=<feature_group>/      # 如 technical / volume
        frequency=<frequency>/
        trading_date=<YYYY-MM-DD>/
            part-*.parquet

    instruments/
        exchange=<exchange>/
        as_of_date=<YYYY-MM-DD>/
            part-*.parquet

    manifests/
        manifest-*.parquet
```

字段/分区说明：

- **market_data** 分区列：`(asset_class, exchange, frequency, trading_date)`。
- **feature_data** 分区列：`(feature_group, frequency, trading_date)`。
- **instruments** 分区列：`(exchange, as_of_date)`。
- **manifest** 记录每个 `(partition, feature_name, version, params_hash)` 的
  `computed_at / row_count / source`，用于去重和版本追踪。

> ⚠️ **重要（当前实现，非理想设计）**：`feature_data` 的 `instrument_id`
> **不在分区路径里**，而是在数据体的 `symbol` 列里（`bars_to_polars` 已把
> `instrument_id` 映射为 `symbol`）。因此按标的查询时是对 `symbol` 列做过滤。
> 后续如果数据规模变大、单 instrument 数据量上升，可以把 `instrument_id`
> 升级为分区列，`FeatureDataReader` 的查询签名保持不变。

> 关于跨 feature_group 查询：不同 `feature_group` 的特征列不同。
> `FeatureDataReader` 会对每个 group 用其子根目录单独扫描（schema 同构），
> 再按 `(symbol, ts_event)` 合并成“一行/时间戳、特征列齐全”的特征矩阵，
> 避免跨异构 schema union 丢列的问题。

## 4. 使用示例

### 4.1 读取 CSV 历史行情

```python
from data_engine import load_events

warmup, live = load_events({
    "mode": "csv_bars",
    "path": "data/bars.csv",
    "instrument_id": "IH2303.CFFEX",
    "timestamp_column": "event_time_ns",
    "timestamp_unit": "ns",
})
```

### 4.2 读取 Hive Parquet 历史行情

```python
from data_engine import load_events

warmup, live = load_events({
    "mode": "hive_parquet_bars",
    "root": "historical_data/market_data",
    "instrument_id": "IH2303.CFFEX",
    "filters": {"trading_date": "2026-05-26"},
})
```

### 4.3 BarEvent 转 Polars（桥接）

```python
from data_engine import bars_to_polars, polars_to_bars

df = bars_to_polars(warmup)        # instrument_id->symbol, event_time_ns->ts_event
bars = polars_to_bars(df)          # 无损回转
```

### 4.4 构建历史特征数据（端到端 CLI）

```bash
python scripts/build_historical_features.py \
    --csv data/bars.csv \
    --feature-root historical_data/feature_data \
    --manifest-root historical_data/manifests \
    --trading-date 2026-05-26 \
    --instrument-id IH2303.CFFEX \
    --frequency 1m \
    --features sma_20,rsi_14,vwm_20 \
    --mode overwrite
```

也可以用 `--market-root historical_data/market_data` 从 Hive 行情读取。
脚本报告会打印：输入 rows、请求/实际计算的 features、输出 feature 列、
写入 partitions（raw / feature 分项）、manifest rows、run_id、feature_root、
manifest_root。

### 4.5 查询历史特征数据

```python
from feature_engine.storage import FeatureDataReader

reader = FeatureDataReader(
    "historical_data/feature_data",
    manifest_root="historical_data/manifests",
)

# 特征矩阵：每个 (symbol, ts_event) 一行，跨 feature_group 的列已合并
df = reader.scan_features(
    trading_date="2026-05-26",
    frequency="1m",
    instrument_id="IH2303.CFFEX",
    columns=["symbol", "ts_event", "sma_20", "rsi_14", "vwm_20"],
)

# 某分区下有哪些特征可用（优先读 manifest）
avail = reader.available_features(trading_date="2026-05-26", frequency="1m")
```

### 4.6 mock live_gateway 实时流

```python
from data_engine import load_events

warmup, live = load_events({
    "mode": "live_gateway",
    "provider": "mock",                 # 本地可测，无需服务器
    "instruments": ["IH2303.CFFEX"],
    "frequency": "tick",
    "warmup_bars": 20,
    "live_bars": 20,
    # 真实 provider 时：password_env="CTP_PASSWORD"（只放环境变量名，不放明文）
})
for event in live:
    ...  # 消费实时事件
```

### 4.7 CCXT 下载合约信息并落盘

```python
from data_engine.instruments import (
    CcxtInstrumentProvider,
    write_instruments_parquet,
)

provider = CcxtInstrumentProvider("binance", market_type="swap")
instruments = provider.load_instruments()      # ccxt 懒加载，公共元数据无需 API key

write_instruments_parquet(
    instruments,
    "historical_data/instruments",
    exchange="binance",
    as_of_date="2026-06-12",
)
```

对应的配置示例：

```yaml
instrument_source:
  provider: ccxt
  exchange_id: binance
  market_type: swap
  symbols:
    - BTC/USDT:USDT
    - ETH/USDT:USDT
```

## 5. 当前未完成 / 边界

- **真实 CTP / 柜台 provider 尚未实现**：`live_gateway` 目前只有 `mock`
  provider 可本地运行，`ctp` / `ctpx` / `internal` 为占位（配置不全或依赖缺失时
  抛清晰错误）。真实接入将在服务器环境通过
  `data_engine/sources/providers/<provider>.py` 实现，本次不强依赖任何第三方
  CTP 库。
- **远程服务器真实行情验证尚未完成**：相关验证命令需在远程 Windows 服务器
  手动执行（见仓库 `SKILL.md`）。
- **分布式调度尚未完整实现**：当前以单机批/流式为主。
- **生产级数据质量报告尚未完整实现**。
- **Nautilus native execution 不属于本次数据接入范围**：本次只做数据接入 /
  历史数据体系，不改策略执行层、不碰 Nautilus 原生回测。
- 合约信息接入：CCXT provider 已实现；国内期货 / 柜台 provider 仅保留接口。

## 6. 本轮新增能力（解耦 + 可复用化）

> 配套文档：[`MODULE_BOUNDARIES.md`](MODULE_BOUNDARIES.md)（模块边界与边界测试）、
> [`HISTORICAL_DATA_LAYOUT.md`](HISTORICAL_DATA_LAYOUT.md)（平级目录结构）。

### 6.1 分钟线构建（`data_engine.transforms`，纯标准库，无重依赖）

```python
from data_engine.transforms import aggregate_ticks_to_bars, resample_bars

res = aggregate_ticks_to_bars(ticks, frequency="1m", default_instrument="IH2303.CFFEX")
res.bars                 # list[BarEvent]
res.rows                 # 标准 OHLCV 行（含 turnover/trading_date/frequency）
res.volume_is_synthetic  # 输入无真实 size 时为 True（成交量=tick 计数，绝不冒充）
res.issues               # OHLC 合法性 / 重复时间戳 / 时间单调性 校验问题
five = resample_bars(res.bars, "5m")   # 1m -> 5m/15m 粗化
```

- 支持 tick / quote-tick / bar 输入（鸭子类型），frequency `1m`/`5m`/`15m`/`1s`/`1h`。
- OHLC 由构造保证 `low <= open/close <= high` 并显式校验。
- `import data_engine` 与分钟线聚合**零重依赖**，已本地（标准库）测试通过。

### 6.2 解耦修复

- `data_engine.adapters.dataframe_adapter` 的 `polars` 改为**懒加载**，因此
  `import data_engine` 不再需要安装 polars（纯 Python 环境即可接入 CSV / 分钟线）。

### 6.3 服务化（`feature_engine.services`）

```python
from feature_engine.services import MinuteBarBuilder, HistoricalFeatureBuilder

# tick -> 分钟线 -> market_data（Hive Parquet）
MinuteBarBuilder(asset_class="future", exchange="CFFEX").build_and_write(
    ticks, instrument_id="IH2303.CFFEX", market_root="historical_data/market_data",
    frequency="1m", trading_date="2026-05-26")

# market_data / DataFrame / events -> 特征 -> feature_data（新版平级分区）
HistoricalFeatureBuilder(["sma_20", "rsi_14", "vwm_20"]) \
    .build_from_market_store("historical_data/market_data",
        instrument_id="IH2303.CFFEX", frequency="1m", trading_date="2026-05-26")
```

CLI（只做 argparse + 调 service）：`scripts/build_minute_bars.py`、
`scripts/validate_data_engine.py`、`scripts/validate_feature_engine.py`。

### 6.4 平级历史数据布局（新版）

新增 `feature_engine.storage.layout` 的路径构造与 `MarketDataReader`：
market_data 与 feature_data 按相同维度（含 `instrument_id`）分区，真正平级。
旧布局仍可读（`FeatureDataReader` 接口不变），新写入默认用新分区。详见
[`HISTORICAL_DATA_LAYOUT.md`](HISTORICAL_DATA_LAYOUT.md)。

> 注：§3 描述的是**现有（legacy）** feature_data 分区
> `(feature_group, frequency, trading_date)`；§6.4 是本轮新增的**平级**分区。
> 现有 `build_historical_features.py` 仍走 legacy 分区（不破坏），统一为 backlog。

## 附：模块边界约束（务必遵守）

- `data_engine` 不依赖 `feature_engine`，不依赖 Nautilus Trader。
- `feature_engine.compute` 不依赖 Nautilus Trader 执行模块。
- 数据接入逻辑不写进策略。
- 历史行情数据与历史特征数据都以 Hive-style Parquet 管理。
- 账号密码不写入配置文件，只通过环境变量（`password_env`）提供。
