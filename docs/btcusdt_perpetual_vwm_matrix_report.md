# BTCUSDT USD-M 永续合约 VWM 实验矩阵报告（周期 × 窗口）

## 1. 实验目标

判断 VWM 在 BTCUSDT 永续合约上的表现是“7 天样本失效”还是“跨周期/窗口普遍不稳定”。
方法：固定单品种 BTCUSDT，扫 **bar_type（5m/15m/1h）× window（7d/30d/90d）** 共 9 组实验，
用统一指标表（含基准超额、手续费情景、持仓暴露）横向对比。

## 2. 数据源 / 下载范围

- 交易所/市场：BINANCE / USD-M 永续（futures_um）；品种：BTCUSDT（`BTCUSDT-PERP.BINANCE`）
- 来源：**Binance Vision public read-only** `data/futures/um/daily/klines/BTCUSDT/{5m,15m,1h}/`
- **无 API key、无 private endpoint、无账户/余额/持仓/下单/撤单/杠杆/实盘**
- 下载范围：2024-06-01 ~ 2024-08-29（90 天），三个周期；逐日 skip-existing，无覆盖
- 行数全部与理论值精确一致：5m 25920 / 15m 8640 / 1h 2160（90d），子窗口同样精确

## 4. 回测命令

矩阵 config：`configs/backtests/vwm_btcusdt_perpetual_matrix.yaml`（3 个 bar_type job）。
runner 单次只用一个全局窗口，故按窗口分 3 次运行（`--start/--end` 覆盖）到独立目录：

```bat
uv run --no-sync python scripts\run_vwm_batch_backtests.py --config configs\backtests\vwm_btcusdt_perpetual_matrix.yaml ^
  --start 2024-06-01 --end 2024-06-07 --out outputs\backtests\vwm_btcusdt_perpetual_matrix_w7d  --fail-fast
:: 同理 --end 2024-06-30 -> _w30d ; --end 2024-08-29 -> _w90d

  --backtest-root outputs\backtests --run-prefix vwm_btcusdt_perpetual_matrix_w ^
  --out-dir outputs\backtests\vwm_btcusdt_perpetual_matrix --symbol BTCUSDT --exchange BINANCE --venue-type futures_um
```

9 个 job 全部 success，0 失败。

## 5. 指标说明

- **Excess Return** = 策略 Total Return − 同周期买入持有（close-to-close）。
- **Zero/VIP Fee Return**：手续费敏感性情景（详见单实验报告）；**情景不代表具体账户费率**。
- **Commission / Gross PnL**：手续费相对毛实现盈亏的压力。
- **Exposure% / Short%**：持仓时间占比；本矩阵 **9 格全部纯空头（Long Trades = 0）**。
- Sharpe 等为各窗口年化（7d 为短样本，仅供参考）。
- **未建模** funding / 保证金 / 强平 / mark-index。

## 7. Ranking 前 3（net_score = 0.4·excess + 0.25·(−maxdd) + 0.2·PF + 0.15·(−手续费压力)，归一化）

1. **15m × 90d** — excess **+21.0%**, Sharpe 1.71, PF 1.63, net_score 0.885

## 8. 主要观察（重点问题逐条回答）

1. **5m 是否过度交易？是。** 5m 交易数最多（90d 390 笔 vs 15m 128 / 1h 35），手续费压力最高
   （Comm/Gross 5m 90d = **2.29**、30d = 2.80）。**5m×90d 零手续费 +11.65%，但实际 −12.95%
   ——手续费把毛盈利彻底吃成大亏**，是过度交易的典型证据。
2. **15m / 1h 是否降低成本？是，且显著。** 15m×90d Comm/Gross 0.50、1h×90d 0.39（vs 5m 2.29）；
   交易数大幅下降，**两者 90d 净收益转正**（+8.84% / +3.35%）。
3. **更长窗口 Excess 是否改善？是，单调改善。** 15m: 7d −5.4% → 30d +7.0% → 90d **+21.0%**；
   1h: −4.5% → +4.7% → **+15.7%**；5m: −6.6% → +1.7% → −0.6%。7 天窗口只是短样本噪声。
4. **是否仍偏空？是，9 格全部纯空头（Long Trades = 0）。** 这是关键：基准在 30d/90d 为
   **下跌**（−7.2% / −12.3%），空头策略自然跑赢下跌市；而 7d 窗口 BTC **上涨 +2.5%**，空头即亏。
   → **超额收益高度依赖行情方向（regime），不等于已验证的 alpha。**
5. **零手续费下是否仍亏？分情况。** 长窗口 + 粗周期已转正（15m×90d 零费 +17.0%、净 +8.8%）；
   5m 的问题是**手续费**（零费 +11.65% 但净 −12.95%）；短 7d 窗口零费仍小亏（信号方向问题）。
6. **相对买入持有是否有超额？9 格中 5 格为正。** 最优 15m/1h×90d 大幅跑赢买入持有——但主要因
   基准本身下跌、策略恰好做空。

## 9. Caveat

- **未建模** funding / 保证金 / 强平 / mark-index；对空头过夜，funding 影响尤其需要补建模。
- **regime 依赖**：策略结构性做空，2024-06~08 BTC 下行使其受益；样本未覆盖明显上行段（除 7d）。
- 短窗口（7d）年化/Sharpe 为外推，不具统计意义；net_score 仅排序辅助。
- 仅 1 个品种、1 组参数、3 个窗口；不是稳健性证明，是初筛。

## 10. 下一步建议

1. **优先在 15m / 1h 上推进**，放弃 5m（手续费结构性吞噬收益，除非费率极低或显著降低换手）。
2. **做 regime 切分验证**：选取 BTC 明显上行/震荡的独立窗口，检验空头偏置是否在非下跌行情仍可接受；
   否则需要把 VWM 做成可双向（多/空）或加入方向过滤。
3. **建模 funding / 保证金 / 强平** 后复核 15m/1h×90d 的净收益是否仍为正。
4. **谨慎进入参数优化**：已出现“15m/1h + 长窗口”有正净值、正超额、PF>1.3 的信号，值得进入
   小范围参数/窗口稳健性测试——但务必先解决 regime 依赖与永续机制建模，避免对单一下跌行情过拟合。
5. **不要**据此单一矩阵（单品种/单参数/下跌行情）下“VWM 有效”的定论。

## 11. 老板可看的结论

> 本阶段把 VWM 实验从单一 5m/7d 扩展为周期 × 窗口矩阵（5m/15m/1h × 7d/30d/90d，9 格），全部使用
> Binance Vision public read-only K 线、未用 API key 或私有接口。结论：**7 天失效主要是短样本 +
> 上涨周噪声**；放到 30/90 天，**15m 与 1h 表现明显优于 5m**——5m 因过度交易被手续费吃掉（90d 零费
> +11.6% 但净 −12.9%），而 15m×90d 净 +8.8%、超额 +21%、Sharpe 1.71、PF 1.63。但策略 **9 格全部纯空头**，
> 而 30/90 天 BTC 恰好下跌，**超额收益高度依赖下跌行情**，不等于已验证的 alpha。当前仍未建模 funding /
> 保证金 / 强平 / mark-index，故该矩阵用于策略初筛与方向定位，不作为最终绩效结论。建议下一步聚焦 15m/1h、
> 做 regime 切分与永续机制建模，再决定是否进入参数优化。
